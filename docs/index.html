How it works

Read a little, run a lot.

  1. 01

    Read the lesson

    Short explanations, real examples and a diagram of what's going on. Try it types any example into the shell for you.

  2. 02

    Run it yourself

    Real bash with the real docker CLI. Each lesson has its own folder of Dockerfiles, app code and compose.yaml files.

  3. 03

    Clear the missions

    Dockerize asks the engine what's actually there: is dz-web running, does it publish 8080, is it on dz-net.

Missions

Checked against the engine, not your typing.

No quizzes, no string matching. You pass when the container, image, volume or network really exists the way the mission asks, so any command that gets there counts. Hints and solutions stay hidden until you ask, and progress is saved.

Diagrams

See what's happening under the hood.

Every lesson has a diagram of the mechanism behind the commands: how the client talks to the daemon, how layers stack, how containers find each other by name. Plus a Reference tab with the flags you'll actually use, and notes on what's different when Docker runs in a Linux VM on your Mac.

Engine

Your whole engine on one page.

Containers, images, volumes and networks, live, so you can watch them appear as you work. Stop, remove or inspect types the matching command into the shell, so you learn the command as you click. Engine down? Start it from here.

A real shell, a real engine

Not a simulator. /bin/bash and the docker CLI talking to your own engine, with your normal config and context.

Its own home folder

The shell's $HOME is a sandbox with one workspace per lesson. Reset a lesson to get its starting files back.

Ready in one click

Lessons offer to pull the images they need. Start Docker opens OrbStack, Docker Desktop or Rancher Desktop, or types colima start.

Cleans up after itself

Everything the lessons create is named dz-…. Clean Up Lab Resources removes only those.

Try it, then tweak

Examples type themselves into the prompt without pressing Return, so you can read and edit them first.

Keyboard friendly

⌘1–⌘4 switch pages, ⌘[ ⌘] move between lessons, ⌘\ hides the sidebar.

Install

Up and running in a minute.

  1. Install a Docker runtime

    Already have one? Skip ahead. Otherwise install OrbStack (brew install --cask orbstack), Docker Desktop or Colima. Dockerize finds the docker CLI on its own.

  2. Download the DMG

    Get Dockerize.dmg from the latest GitHub release. One universal download for Apple silicon and Intel.

  3. Drag Dockerize to Applications

    Open the DMG, drag Dockerize onto Applications, then eject the disk image in Finder's sidebar. You can delete the DMG afterwards.

  4. Open Dockerize

    Launch it from Applications, Launchpad or Spotlight (⌘ Space, then type “Dockerize”). The first launch needs one extra step, below.

If macOS says Dockerize can't be opened

Dockerize is free and isn't notarized by Apple, so Gatekeeper blocks the first launch. You only need to allow it once.

macOS 15 Sequoia and later: open Dockerize once and click Done. Then go to System Settings → Privacy & Security, scroll to the message about Dockerize, click Open Anyway, and confirm with your password.

macOS 14 Sonoma: in Applications, Control-click Dockerize, choose Open, then click Open again.

Prefer the Terminal?

Clear the quarantine flag after copying the app to Applications:

xattr -dr com.apple.quarantine /Applications/Dockerize.app
Build from source

Needs Xcode 15.3 or later, or the Swift 5.10 toolchain.

git clone https://github.com/mmerioles/dockerize.git cd dockerize swift run

To make your own DMG, run scripts/build-dmg.sh.

Uninstall

First choose Docker → Clean Up Lab Resources in Dockerize to remove the dz-… containers, images, volumes and networks the lessons made. Then drag Dockerize from Applications to the Trash. To also remove your practice files and progress:

rm -rf ~/Library/Application\ Support/Dockerize defaults delete io.github.mmerioles.dockerize

Your Docker runtime and everything else on your engine stay as they were.
